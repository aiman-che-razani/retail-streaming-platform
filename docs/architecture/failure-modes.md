# Failure Modes

> Status: **Accepted** (Phase 1). Every row must have an automated test or a documented manual drill (see the "Verified by" column; tests are implemented in Phases 9–10).
> Design principle: **fail predictably, never corrupt silently.** A component either processes a record correctly, routes it to a DLQ with a reason, or stops and alerts, with its position preserved so it can resume.

## Principles behind the table

1. **Offsets are only committed after effects are durable** (Spark checkpoint commit after the sink; redrive commit after ack; stream offset advances only on transaction commit).
2. **Every sink is idempotent**, so "retry the whole unit of work" is always safe. That is what turns at-least-once delivery into exactly-once *effects*.
3. **Transient failures are retried at the unit-of-work level** (batch, COPY, task run). **Deterministic failures go to the DLQ** (retrying a malformed record is pointless).
4. **Decouple failure domains**: Snowflake outages don't stop Spark (landing zone); PostgreSQL outages don't affect the warehouse path (separate app and checkpoints).
5. **Everything is counted**, so reconciliation can explain every record: loaded, rejected, duplicate, or late.
